# Decision Feedback Loop — Agent 行为规范 V4

> Weee! 决策反馈循环机制的核心行为规范。安装到所有 A 类（决策建议型）agent。
> 起草日期：2026-08-19 | 版本：V4 | 状态：待试点验证

## 一、机制概述

本规范源自 Weee! 采购部门的决策反馈循环机制，核心思想：

> 不要只记录 AI 做了什么决策，要记录人为什么否决了 AI 的判断——这个"为什么"才是让 AI 真正变聪明的数据。

三步闭环：
1. **AI 给建议** → 正常对话消息（第 1 次推送）+ 互动卡片（第 2 次推送）
2. **人做反馈** → 采纳（可填说明）/ 部分采纳·不采纳（必须写明"部分采纳"或"完全不采纳" + 原因）
3. **反馈写台账** → 自动登记到「AI 决策反馈台账」多维表格

### 不压缩原则

**本技能是附加行为规范，不是回答模板。不得因为使用了本技能，就把 AI 本来要回答的内容压缩、删减或模板化。** 先完整回答用户的问题，再附加防跑偏检查和反馈卡片。

### 台账位置

本技能不预置台账路径——台账位置因人而异。首次使用时，搜索飞书云空间是否已有「AI 决策反馈台账」多维表格；如果没有，创建一个新的。详见「四、台账写入规范」。

## 二、防跑偏规则（最高优先级）

### 规则 1：关键数字必须回源核实

AI 输出的数字不能"看见过就信"。涉及价格、库存、销量、质量指标等关键数字时，必须从数据库重新拉取核实。

**触发条件**：AI 输出中包含具体数字（金额、数量、比率、日期）且该数字可从业务系统查到。

**执行方式**：
1. 在输出数字前，先调用对应数据源（多维表格、ERP、业务系统 API）拉取最新值
2. 将拉取到的值与记忆/上下文中的旧值比对
3. 一致 → 正常输出，可标注"已核实"
4. 不一致 → 以拉取值为准，并说明"原数据有更新"
5. 无法回源 → 数字旁标注"（未核实，建议确认）"

**示例**：
- ✅ "当前库存 12,800 双（已从库存表核实）"
- ✅ "毛利率约 42%（未核实，建议确认）"
- ❌ "毛利率 42%"（未标注是否核实，直接当事实输出）

### 规则 2：AI 不允许"代填"用户反馈

用户点"提交"但没填任何内容时，AI **禁止**自动补全反馈文本。

**核心原则**：

| 字段 | 谁写 | 禁止行为 |
|------|------|----------|
| 采纳说明文本 | 用户 | AI **禁止**在用户没填时自动补全 |
| 否决理由文本 | 用户 | AI **禁止**在用户没填时自动补全 |

## 三、反馈卡片行为规范

### 两次推送模式（V4 核心变更）

决策建议型内容分两次推送，**不在卡片里放建议正文**：

| 推送次序 | 内容 | 形态 |
|----------|------|------|
| 第 1 次 | **AI 建议正文**——完整的决策建议、分析、方案 | 正常对话消息（文字 / Markdown） |
| 第 2 次 | **决策反馈卡片**——只用于收集用户的采纳/不采纳反馈 | 飞书互动卡片 |

**为什么分开**：
- 建议正文是给人读的内容，放对话里阅读体验好，不挤在卡片里
- 卡片只负责"收集反馈"这一个动作，结构干净、字段清晰
- 采纳和不采纳各自一个独立板块，各有文本框和提交按钮

### 何时发卡片

当 agent 输出的是**可采纳/可否决的决策建议**时（选品推荐、质量风险评估、数据分析结论等），必须附带互动卡片。

### 适用范围（明确边界）

**必须跳卡片**（决策建议型，agent 的判断/方案/推荐被采纳后会执行关键动作）：
- 选品/采购/备货建议
- 质量风险评估与处理方案
- 经营决策/数据分析结论
- 团队管理/激励机制方案
- 战略规划 / AI 落地路径选择
- 任何"执行与否影响业务结果"的建议

**不跳卡片**（常规推送型，用户看了知道就好、不会因为"不采纳"而改变执行）：
- 日常提醒（"明天记得发账单"、"记得催 X"）
- 信息推送（"已同步到 Y"、"已开通 Z"）
- 进度同步（"X 已完成 30%"）
- 简单提示（"格式注意"、"别忘了存档"）
- 工具/操作步骤说明
- 重复性事务（日报、周报、记账等）

**判断口诀**：用户读完之后**有"采不采纳"的决策动作** → 跳卡片；读完之后**只有"知道了"的反应** → 文字推送。

### 卡片结构（V4）

卡片分为**两个独立板块**，各自带文本输入框 + 提交按钮：

| 区段 | 用途 |
|------|------|
| Agent 信息 | Agent 名 / 场景 / 归属层 |
| **采纳** 板块 | 1 个多行文本输入框（填写采纳说明，可选）+ 1 个「提交」按钮 |
| **不采纳** 板块 | 1 个多行文本输入框（填写结论 + 原因）+ 1 个「提交」按钮；段落中标注需填字段 |

**不采纳板块的段落字段**：在文本输入框上方用 Markdown 标注用户需填写的字段——`① 结论（部分采纳 / 完全不采纳）② 具体原因`。

### 版本变更历史

#### V3 → V4 变更

| 维度 | V3（旧） | V4（新） |
|------|----------|----------|
| 建议正文位置 | 放在卡片内的「AI 建议」区段 | **移出卡片**，放第 1 次对话推送 |
| 采纳方式 | 一键点击「采纳」按钮，无输入 | **采纳板块带文本框 + 提交按钮**，用户可填写采纳说明 |
| 采纳/不采纳布局 | 采纳按钮 + 不采纳表单，在同一区域 | **分成两个独立板块（段落）**，各有自己的表单和提交按钮 |
| 推送次数 | 1 次（卡片包含全部内容） | **至少 2 次**（第 1 次对话推建议正文，第 2 次推反馈卡片） |
| 卡片字段 | `ai_suggestion` 在卡片内 | **移除** `ai_suggestion`，卡片只保留 Agent 信息 + 两个反馈板块 |

#### V2 → V3 变更

| 维度 | V2（旧） | V3（新） |
|------|----------|----------|
| 反方意见 | 规则 2 要求 AI 扮演反方、自检盲区，卡片展示反方意见 | **删除**——不再强制反方检查，不压缩 AI 本来要回答的内容 |
| 台账路径 | 硬编码特定多维表格路径 | **不预置**——首次使用时搜索或创建专属台账 |
| 台账字段 | 含"反方意见"字段 | **移除**"反方意见"字段 |
| 行为数量 | 三条行为 | 两条行为 |

#### V1 → V2 变更（历史）

| 维度 | V1（旧） | V2（新） |
|------|----------|----------|
| 按钮组 | 采纳 + 否决并说明理由 | 仅"采纳"按钮 |
| 否决理由标签 | 8 个预设多选项 | **拿掉**，由用户自己写 |
| 文本输入 | 补充说明（可选） | **核心输入** |
| 三类区分 | 否决（统一字段） | 文本内自描述 |

### 飞书卡片平台限制

飞书互动卡片**不支持"点按钮才展开表单"**——两个板块的表单会一直显示在卡片中。V4 方案：采纳板块和不采纳板块各自独立，用户选一个板块填写后点对应的「提交」按钮即可。

### 卡片回调处理（当前环境限制）

**当前环境（lark-cli 构建）不支持卡片回调事件 `card.action.trigger`**——按钮点击/表单提交事件无法被 agent 接收。

**处理方式**：
- 卡片只作为"漂亮的反馈入口"发送，**不依赖回调闭环**
- 收到用户**后续文字反馈**（"采纳" / "部分采纳 + 原因" / "完全不采纳 + 原因"）→ 按下方写入逻辑写台账
- 在卡片下方附**简短文字说明**："卡片按钮点击后我这边收不到回调（平台限制），请直接回复我"——让用户知道正确反馈路径

### 卡片回调逻辑（回调可用时）

用户点击按钮或提交表单后，agent 收到回调，处理逻辑：

1. **采纳提交回调**（action: "adopt_submit"）：
   - 写台账记录：采纳/否决 = 采纳，**否决理由文本 = 用户填的采纳说明原文（如未填则为空，AI 禁止代填）**，状态 = 已关闭
   - 回复用户："已采纳，感谢反馈"
2. **不采纳提交回调**（action: "veto_submit"）：
   - 写台账记录：采纳/否决 = 部分采纳·不采纳，**否决理由文本 = 用户填的原文（如果用户没填则为空，AI 禁止代填）**，状态 = 待处理
   - 回复用户："已记录反馈，将用于改进后续建议"

### 发完卡片后继续对话

**发了反馈卡片后不要停**——继续正常对话，不要等用户对卡片的反馈：

- 卡片是"漂亮的提醒"，不是"阻塞点"
- 如果同时有其他工作要推进，发完卡片后**立即继续**
- 用户对卡片的反馈会在**后续某轮**自然出现，按"卡片回调处理"章节处理即可

### 卡片模板

标准卡片 JSON 模板存储在 `assets/decision_feedback_card_template.json`。

agent 发送卡片时，替换以下字段为实际值：
- `agent_name`：当前 agent 名称
- `scene`：当前场景（选品建议/内容审核/质量分析/数据分析/AI落地建议/内容生成/其他）
- `layer`：归属层（团队大脑/个人助手）

**注意**：V4 卡片不再包含 `ai_suggestion` 字段——建议正文已在第 1 次推送的对话消息中给出。

## 四、台账写入规范

### 台账发现与创建（首次使用）

本技能不预置台账路径——台账位置因人而异。首次使用时按以下步骤发现或创建台账：

1. **查记忆**：先查 agent 记忆文件是否已存台账 base_token 和 table_id，有就直接用
2. **搜索现有台账**：在飞书云空间搜索名为「AI 决策反馈台账」的多维表格
   ```
   lark-cli drive +search "AI 决策反馈台账" --type bitable --as user
   ```
3. **找到 → 直接使用**：记录 base_token 和 table_id，后续写入用这个
4. **没找到 → 创建新台账**：
   ```
   lark-cli base +app-create --name "AI 决策反馈台账" --as user
   ```
   然后按下方字段定义创建字段
5. **记住台账位置**：把 base_token 和 table_id 写入 agent 记忆文件，后续直接使用，不用每次重新搜索

具体命令请 `get_skills("larksuite-cli-guide")` 后查看 `lark-cli drive +search` 和 `lark-cli base` 相关命令。

### 台账字段（V4）

| 字段 | 类型 | 谁写 | 说明 |
|------|------|------|------|
| AI建议摘要 | 文本 | AI | 建议内容概要 |
| 日期 | 日期 | 自动 | 记录创建时间 |
| 场景 | 单选 | AI | 选品建议/内容审核/质量分析/数据分析/AI落地建议/内容生成/其他 |
| Agent名称 | 单选 | AI | 哪个 agent 给出的建议 |
| 归属层 | 单选 | AI | 团队大脑/个人助手 |
| 采纳/否决 | 单选 | AI | 采纳 / 部分采纳·不采纳（"部分采纳"和"完全不采纳"统一记为"部分采纳·不采纳"，由"否决理由文本"区分具体程度） |
| 否决理由文本 | 文本 | **用户** | 用户的真实反馈。采纳时填写采纳说明，不采纳时填写结论+原因。**AI 禁止代填** |
| 反馈人 | 人员 | AI | 谁做的反馈 |
| 改进动作 | 文本 | AI | 后续提炼的改进规则（定期 batch 回流时填写） |
| 状态 | 单选 | AI | 待处理/已回流/已关闭 |

## 五、反馈回流路径

### 起步阶段（Phase 1-2）：定期 batch 提炼
每两周人工 review 台账，提炼共性规则，手动更新 agent 的 skill 或 prompt。

提炼时关注的是**用户的原话**——用户在"否决理由文本"里写明的"部分采纳 + 具体调整方向"是最有价值的信号。

### 中期（Phase 3）：写入记忆文件
agent 收到反馈后自动把"建议X被否决因为Y"写入自己的记忆文件，下次决策时读到。

### 成熟阶段（Phase 4）：RAG 检索
反馈历史做成向量库，agent 每次决策时自动检索相关历史反馈。

## 六、两层架构说明

### 团队大脑（共享型 agent）
团队工作伙伴、企业工作伙伴。所有反馈写入团队台账，全员可查。沉淀公司级经验。

### 个人助手（个人型 agent）
专属工作伙伴、工作伙伴、飞书 OpenClaw。个人反馈双写：一份进个人记忆（个人变聪明），一份进团队台账（组织也在变聪明）。

## 七、成熟度衡量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 否决理由回流率 | 已回流记录数 ÷ 不采纳记录总数 | Phase 2 达 50%，Phase 4 达 80% |
| 重复否决率 | 同一 agent 同一理由不采纳次数 ÷ 该 agent 总不采纳次数 | 下降趋势 = 系统在变聪明 |
| 回源核实覆盖率 | 标注"已核实"的数字 ÷ 输出中包含的关键数字总数 | Phase 3 达 70% |
| **代填违规率** | AI 未经用户授权填入"否决理由文本"的次数 | **必须为 0**——任何非零都要追溯根因 |

## 八、频率自动晋级

每周一定时任务扫描台账最近 30 天不采纳记录，按 Agent名称 + 否决理由文本关键词分组统计。同一 agent + 同一关键词出现 3 次及以上，推送通知给使用者，提示"这个判断维度可能被系统忽略了，建议检查该 agent 的 prompt 或 skill"。
